## 🔧 工程实践：依赖裁剪——被忽视的供应链安全第一课

Andrew Nesbitt 提出了一个被严重低估的软件工程原则：**删除不需要的依赖，是代价最低的供应链安全加固**。

"lockfile 中的每一个包，都是他人持有钥匙的一扇门。"安装脚本以 CI 的权限运行，维护者账号可能被钓鱼，Registry 条目可能易手，下一个补丁版本可能与之前截然不同。即使是一个两年前的重构中已不再调用的依赖，其 CVE 警报仍然会触发，并且其暴露的攻击面与高频调用的依赖完全相同。

Nesbitt 建议：收到 Dependabot CVE 警报后，第一反应应该是检查自己是否还需要这个依赖，而不是急着去看 Changelog。对于一个"基本不用"的依赖上的 CVE，删除它比打补丁更划算——而且能同时关闭当前和未来所有相关警报。

## 💾 历史回眸：Windows 3.0 发布 36 周年

Windows 3.0 于 1990 年 5 月 22 日发布，被普遍认为是微软首个真正可用的 Windows 版本——也是首个取得商业成功的版本。"永远等微软的 3.0 版本"这句行业谚语正是对 Windows 3.0 的经典注解，至今仍被反复引用。

在当时的多平台 GUI 竞争中，Windows 3.0 并非技术最优解，但它做到了两点关键要素：**第一，它比苹果 Mac 的 System 7 早了 356 天上市；第二，它在多任务稳定性上超过了苹果的 Multifinder，甚至在当时优于不少单任务 Mac。** Windows 1.0 和 2.0 稳定到令人失望，而 Windows 3.0 终于可以"开机运行一整天不崩溃"——这在 1990 年是货真价实的进步。

技术竞争的历史一再证明：**足够好加抢先一步，往往打败更优秀但迟到的产品。**
